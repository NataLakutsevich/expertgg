# План выполнения задания: Simplified 3 (Android-приложение + бэкенд + админка)

Источник дизайна: Figma "Lab Expertgg Dev Mode"
Стек: Claude Code · React Native · Python/Django (DRF) · DigitalOcean · MCP Figma
Итог: APK-файл + работающий бэкенд с админкой

---

## 0. Подготовка (0.5 дня)

1. Установить Claude Code (`npm install -g @anthropic-ai/claude-code` или актуальная инструкция с docs.claude.com) и авторизоваться.
2. Подключить MCP-сервер Figma в Claude Code (в задании уже указана ссылка на файл — просто дать Claude Code доступ к MCP Figma, он сам умеет читать `get_design_context`, `get_screenshot`, `get_metadata`, `get_variable_defs`).
3. Завести git-репозиторий с тремя папками: `backend/`, `mobile/`, `docs/`.
4. Завести аккаунт на DigitalOcean (можно по студенческому/free-кредиту), сгенерировать SSH-ключ для доступа к дроплету.
5. Сформулировать для себя роль LLM как консультанта: перед каждым непонятным шагом (SSH, миграции, сборка APK, TLS-сертификат и т.п.) — сначала спросить у Claude "что это и как это работает", потом делать.

Контрольные вопросы себе на этом этапе (задать LLM, если не понятно):
- Что такое SSH и как подключиться к серверу?
- Чем отличается git clone / git pull при деплое?
- Зачем нужен virtualenv в Python-проекте?

## 1. Анализ дизайна в Figma (0.5–1 день)

1. Открыть файл в Figma MCP через Claude Code, попросить агента:
   - выгрузить список экранов (`get_metadata`),
   - получить дизайн-контекст и переменные (цвета, шрифты, отступы) для каждого экрана (`get_design_context`, `get_variable_defs`),
   - сделать скриншоты ключевых экранов для референса (`get_screenshot`).
2. Составить таблицу: экран → компоненты → нужные данные с бэкенда (например: "Экран профиля → поля name/avatar/email → GET /api/profile").
3. На основе таблицы сформировать черновой список сущностей (моделей) для Django: User, Profile, Order, Product и т.д. — зависит от реального макета.
4. Сохранить это в `docs/screens_and_api.md` — этот документ станет техническим заданием для backend и mobile частей.

## 2. Проектирование API (0.5 дня)

1. Попросить Claude Code (как консультанта) предложить REST-контракт: список эндпоинтов, методы, форматы запросов/ответов (JSON), коды ошибок.
2. Утвердить контракт в `docs/api_contract.md` — от него будут отталкиваться и backend, и mobile, чтобы не гнаться друг за другом.
3. Определить auth-механизм (JWT через `djangorestframework-simplejwt` — самый простой вариант для мобильного клиента).

Вопрос для консультации: "Как лучше реализовать авторизацию в Django REST для мобильного клиента — сессии или JWT? Почему?"

---

## 3. Backend: Django + DRF (2–3 дня)

1. `django-admin startproject backend`, добавить приложения по доменам (`accounts`, `catalog`, и т.п. — по факту дизайна).
2. Подключить `djangorestframework`, `django-cors-headers`, `djangorestframework-simplejwt`.
3. Описать модели → миграции → сериализаторы → viewsets/роуты согласно `api_contract.md`.
4. Django admin (бонус из задания) обычно работает "из коробки" — донастроить `admin.py` (list_display, search_fields, inlines) под реальные модели, чтобы админка была удобной, а не дефолтной.
5. Настроить `.env` (SECRET_KEY, DEBUG, DATABASE_URL) через `django-environ` или `python-decouple`, не хардкодить секреты.
6. Локально проверить все эндпоинты (Postman/httpie/curl) на соответствие контракту.
7. Написать минимальные тесты на критичные эндпоинты (auth, основной CRUD).

Вопросы для консультации:
- "С помощью чего бы мне разработать бэкенд?" (Django/DRF — обосновать выбор, обсудить альтернативы FastAPI)
- "Как реализовать API — сделай план?" (просить Claude декомпозировать по моделям/эндпоинтам)

## 4. Mobile: React Native (3–4 дня)

1. Инициализация: `npx react-native init` (или Expo — проще для сборки APK без настройки Android SDK локально).
2. Настроить навигацию (`react-navigation`) по карте экранов из `docs/screens_and_api.md`.
3. Верстать экраны, ориентируясь на скриншоты/переменные из Figma (цвета, шрифты, отступы — брать из `get_variable_defs`, а не "на глаз").
4. Подключить слой сетевых запросов (`axios`/`fetch`) к backend API, обработать состояния загрузки/ошибок.
5. Реализовать авторизацию (хранение JWT — `AsyncStorage`/`expo-secure-store`), защищённые экраны.
6. Прогнать на эмуляторе Android (Android Studio emulator) или на реальном устройстве через `adb`.

Вопросы для консультации:
- "Разница между чистым React Native CLI и Expo — что проще для сборки APK новичку?"
- "Как подключить мобильное приложение к бэкенду, который лежит на удалённом сервере (а не localhost)?"

## 5. Деплой backend на DigitalOcean (1–2 дня)

1. Создать Droplet (Ubuntu LTS, минимальная конфигурация достаточно для учебного проекта).
2. Подключиться по SSH, поставить Python, Postgres (или оставить SQLite для простоты — на бонус не влияет), nginx, gunicorn.
3. Склонировать репозиторий на сервер (`git clone`), настроить virtualenv, `pip install -r requirements.txt`, `.env` на сервере.
4. Настроить gunicorn как systemd-сервис + nginx как reverse proxy; при желании — Let's Encrypt (certbot) для HTTPS, если есть домен.
5. Прогнать миграции на проде, создать суперпользователя для админки (`createsuperuser`), убедиться, что `/admin/` открывается.
6. Прописать в мобильном приложении реальный URL бэкенда (вместо localhost) и пересобрать.

Вопросы для консультации (буквально из задания):
- "Как мне разместить бэкенд на сервере?"
- "Разлей код на сервер — что от меня нужно?"
- "Что такое SSH?"

## 6. Сборка APK (0.5–1 день)

1. Если Expo — `eas build -p android --profile production` (нужен Expo-аккаунт) или локальная сборка `expo run:android --variant release`.
2. Если чистый RN CLI — `cd android && ./gradlew assembleRelease`, подписать APK ключом (`keytool` + настройка `build.gradle`).
3. Проверить итоговый APK на реальном устройстве или эмуляторе: установка, вход, работа с реальным (задеплоенным) API.

Вопрос для консультации: "Чем отличается debug и release сборка APK, и почему release нужно подписывать?"

## 7. Финальная проверка перед сдачей

- [ ] Все экраны из Figma реализованы (сверить со скриншотами)
- [ ] Backend отвечает на все эндпоинты из `api_contract.md`
- [ ] Admin-панель Django доступна и позволяет управлять данными
- [ ] Backend работает на DigitalOcean по публичному адресу (не localhost)
- [ ] Мобильное приложение подключено к продовому бэкенду, а не к локальному
- [ ] APK собран в release-режиме, подписан, установлен и протестирован на устройстве
- [ ] Есть краткая документация: `docs/api_contract.md`, `docs/screens_and_api.md`, README с инструкцией запуска
