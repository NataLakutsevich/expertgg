# Экраны и API-контракт (по присланным скриншотам)

Судя по названиям фреймов (DK. SignIn, Play/no match, DK.History, DK. Ledearboard, DK. Account) и иконке скрещенных мечей — это приложение для дуэлей/PvP-матчей ("DK" похоже на кодовое имя проекта, например Duel Klub). Внутренняя валюта — "gg" (очки/монеты).

Нижняя навигация одинакова на всех экранах: **Play · History · Leaders · Account** — значит это 4 таба одного `BottomTabNavigator` в React Native.

---

## 1. SignIn

Поля: Email, Password, кнопка "Log in".

**Модель:** стандартный Django `User` (или кастомный `AbstractUser` с email как username).

**API:**
- `POST /api/auth/login/` — body `{email, password}` → `{access, refresh}` (JWT, `djangorestframework-simplejwt`)
- `POST /api/auth/refresh/` — body `{refresh}` → `{access}`

✅ Уточнено: регистрации в приложении нет — пользователей создаёт админ через Django admin. Значит `POST /api/auth/register/` не нужен, экран SignIn — это единственная точка входа, и весь MVP-контракт auth сводится к login/refresh/logout.

Практическое следствие для админки: при создании пользователя в Django admin нужно сразу создавать и связанный `Profile` (через `post_save`-сигнал на `User` или инлайн `ProfileInline` в `UserAdmin`), иначе после логина у нового игрока не будет `gg_balance`/`avatar` и вьюхи по профилю/лидерборду будут падать на `Profile.DoesNotExist`.

## 2. Play (пустое состояние "No Matches")

Таб "Play", по умолчанию — пустое состояние с иконкой мечей и текстом "No Matches". Значит должен быть и непустой сценарий: поиск матча / активный матч / экран самой дуэли — этих скринов пока нет.

**Модель:** `Match` (или `Duel`):
- `id`
- `player1` (FK User), `player2` (FK User, nullable до момента, пока не нашёлся соперник)
- `status` (enum: `searching` / `active` / `finished`)
- `score1`, `score2` (или `winner` FK User)
- `created_at`, `finished_at`

**API:**
- `GET /api/matches/current/` — вернёт активный/ищущийся матч пользователя, либо `null` → на клиенте это и есть состояние "No Matches"
- `POST /api/matches/search/` — поставить пользователя в очередь поиска соперника
- `DELETE /api/matches/search/` — отменить поиск
- (позже, когда появится экран самой игры) `POST /api/matches/{id}/move/` или аналог — зависит от механики дуэли, которой пока не видно на макетах

⚠️ **Главный открытый вопрос**: как устроена сама дуэль (что происходит после того, как соперник найден)? Без экрана gameplay нельзя спроектировать логику матча — сейчас можно закрыть только "обёртку" (поиск/история/результат), а не саму игру.

---

## 3. History (пустое состояние "No History")

Таб "History" — список прошлых матчей пользователя, сейчас пусто.

**API:**
- `GET /api/matches/history/` → список завершённых `Match`, где пользователь — участник:
  ```json
  [{"id": 1, "opponent": "Adel V", "result": "win", "score": "3:1", "date": "2026-08-01T10:00:00Z"}]
  ```

Отдельная модель не нужна — это фильтр по `Match.status = finished`.

---

## 4. Leaderboard

Список игроков: ранг, аватар, имя (у текущего пользователя, вероятно, имя подсвечено синим — "Adel V" выделен), значение "gg".

**Модель:** поле `balance` (или `rating_points`) на профиле пользователя:
- `Profile.user` (FK, one-to-one с User)
- `Profile.avatar`
- `Profile.gg_balance` (int) — то самое "gg"

**API:**
- `GET /api/leaderboard/?limit=50` → отсортированный по `gg_balance` список:
  ```json
  [{"rank": 1, "username": "ALLMIX", "avatar": "...", "gg": 1000000, "is_current_user": false}]
  ```
  Поле `is_current_user` — чтобы клиент мог подсветить строку текущего игрока, как на макете.

---

## 5. Account

На скрине видна только кнопка "Log out" — вероятно, экран ещё не доделан в макете (обычно здесь профиль, аватар, статистика, баланс "gg", настройки).

**API:**
- `GET /api/account/me/` → `{username, email, avatar, gg_balance, wins, losses}`
- `POST /api/auth/logout/` — инвалидация refresh-токена (blacklist)

⚠️ Стоит уточнить у преподавателя/куратора, планируется ли доработка этого экрана в макете, или в MVP достаточно только Logout.

## Что нужно уточнить/доснять из Figma, чтобы контракт был полным

1. Экран/поток самой дуэли (что происходит после "матч найден") — это ядро продукта и главный пробел в текущем API.
2. Полный экран Account (профиль, статистика) — сейчас есть только Logout.
3. Как игроки получают "gg" — за победу в дуэли? Есть ли покупка/донат — на это может влиять модель монетизации и, соответственно, admin-панель (нужны ли модели транзакций).

## Минимальный набор моделей Django (на основе того, что уже видно)

- `User` (email как login)
- `Profile` (avatar, gg_balance, wins, losses)
- `Match` (player1, player2, status, score, created_at, finished_at)

Админка (бонус из задания) сразу даёт CRUD по этим моделям — этого достаточно, чтобы куратор/тимлид мог руками поправить баланс игрока или результат матча без доступа к базе.
